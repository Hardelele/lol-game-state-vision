# Свои, враги, сам и сторона (#790)

Модуль `lolvision/sides.py`, проверка — `tools/eval_sides.py`, тесты —
`tests/test_sides.py`.

## Что было не так

Детектор юнитов (`unit_net.py`) выдаёт `team` ORDER/CHAOS по одному логиту
(«CHAOS против ORDER»), выученному на наблюдателе канала, где синяя полоска —
ORDER, красная — CHAOS. Значит, `team` детектора — это «синий или красный по
выучке наблюдателя», а не сторона. На виде игрока цвета относительны:
союзники синие, враги красные, своя плашка зелёная (в режиме для дальтоников
— жёлтая), и за CHAOS враги тоже красные. Если читать `team` как сторону,
у стримера за красных команды перевёрнуты, а свой чемпион — то «ORDER», то
«CHAOS».

Замер на 30 кадрах стримов вида игрока (`runs/units/eval/player`, ответы
детектора `net` при пороге 0.3, без маски HUD; кадры 960×540, растянуты до
1080p): зелёных плашек по цвету в пикселях 14 (одна из них — ложный ответ
детектора на табло Tab) — детектор дал им ORDER 12 раз и CHAOS 2 раза;
жёлтых 3 — все CHAOS. Синие плашки — все ORDER (6), красные — все
CHAOS (17). То есть детектор различает синий и красный, а «своего» не
различает и уверенно называет союзником или врагом.

## Правило

Каждый юнит получает `relation` (ally / enemy / self) и `side`
(ORDER / CHAOS), каждое — значение или `null` с причиной
(`relation_reason`, `side_reason`). `team` остаётся сырым ответом детектора.

| Случай | relation | side |
|---|---|---|
| Вид наблюдателя | `null` — «вид наблюдателя: своего игрока нет» | `team` детектора |
| Вид игрока, полоска синяя, API: своя команда X | ally | X |
| Вид игрока, полоска красная, API: X | enemy | другая сторона |
| Вид игрока, плашка чемпиона зелёная, API: X | self | X |
| Вид игрока, зелёная полоска у миньона/варда | `null` — «цвет вне ожидаемого: green у minion» | `null` |
| Вид игрока, цвет вне таблицы (жёлтый, фиолетовый) | `null` — «цвет вне ожидаемого: yellow» | `null` |
| Вид игрока, полоска не найдена / две корзины сопоставимы | `null` — «полоска не прочитана» / «цвет полоски неоднозначен» | `null` |
| Вид игрока, синий/красный пробы против красного/синего детектора | `null` — «цвет полоски и ответ детектора расходятся» | `null` |
| Вид игрока, нет кадра для пробы | `null` — «нет кадра для пробы цвета» | `null` |
| Вид игрока, нет команды своего игрока в API | по цвету, как выше | `null` — «нет команды своего игрока: <причина API>» |
| Вид неизвестен | `null` — «вид неизвестен» | `null` — «вид неизвестен» |
| Запись прошла мимо `sides.assign` | `null` — «не определялось» | `null` — «не определялось» |

Таблица цветов — одна: `unit_bars.TEAM_BY_COLOR` (наблюдатель: синий ORDER,
красный CHAOS; игрок: green SELF, blue ALLY, red ENEMY) и корзины оттенка
`unit_bars.COLORS`. Жёлтый в таблицу игрока не внесён нарочно: по одному
источнику так выглядит своя плашка в режиме для дальтоников, но палитра
этого режима для врагов и союзников не проверена — отказ лучше выдумки.

`team` детектора на виде игрока — только проверка: если проба дала синий
или красный, а детектор — другой из этих двух, это отказ. Почему не
источник: детектор не умеет «зелёный», а для миньонов неизвестно, выучил он
цвет полоски или цвет тела (тела миньонов окрашены по стороне, а не по
отношению к игроку). Если выучил тело, за CHAOS союзные миньоны будут
расходиться с пробой — это будут отказы, а не перевёрнутая команда; их доля
видна в `tools/eval_sides.py`.

## Проба цвета

`probe_color(rgb, kind, x, y)` ищет в окне над точкой тела заливку полоски:
горизонтальную плотную полосу насыщенного цвета (маски `unit_bars.color_masks`),
и берёт корзину с самой широкой заливкой; две корзины сопоставимой ширины
(меньше чем вдвое) — отказ. Геометрия задана при 1080p и масштабируется по
высоте кадра.

* Чемпион: окно −90…+90 px по x, −170…−50 px по y от точки тела; заливка ХП
  плашки вида игрока — 9–13 строк (берутся 6–16), заполнена на 0.7–0.95.
  Полоска ресурса под ней (4–5 строк, синяя у маны) отсекается высотой —
  иначе свой стал бы «союзником».
* Миньон и вард: окно вокруг места полоски по `unit_bars.BODY`, заливка
  2–7 строк в тёмной рамке сверху и снизу (как в `unit_bars`): у травы и
  бликов рамки нет.

На тех же 30 кадрах (худший случай: 540p, растянутые, с пережатием JPEG):

| Класс | Ответов детектора | Цвет прочитан | Из них противоречит детектору (синий/красный) | Цвет вне таблицы |
|---|---:|---:|---:|---:|
| Чемпион | 45 | 40 | 0 | 3 (жёлтые плашки) |
| Миньон | 212 | 35 | 0 | 6 (отказы; поштучно глазами не разбирались) |
| Вард | 19 | 0 | — | — |

Проверка глазами листа плашек чемпионов: из 40 прочитанных цветов 38 верны;
один «зелёный» — ложный ответ детектора на табло Tab (там зелёные полосы ХП
союзников), один неясен (плашка под эффектом оглушения). Миньоны и варды на
этих кадрах читаются плохо: тонкая полоска в 540p размыта; на своём экране
1080p ожидается лучше — не проверено.

## Трекер

`unit_tracker` раньше сопоставлял юнитов внутри (класс, `team`). На виде
игрока `team` своего чемпиона прыгает между ORDER и CHAOS, и трек рвался.
Теперь пары ищутся внутри класса; пара запрещена, если у юнита и трека
известны и различаются `side` или `relation`. Неизвестное не запрещает:
трек берёт первое известное значение и дальше его не меняет. Записи без
`sides.assign` (обе причины «не определялось») сопоставляются как раньше, по
`team`. События `unit_new` / `unit_death` несут `relation` и `side` трека.

## Формат

`schema` остаётся 1: поля только добавлены (`color`, `relation`,
`relation_reason`, `side`, `side_reason` у юнита; `relation`,
`relation_reason`, `side`, `side_reason` у трека; `relation`, `side` у
событий юнитов), смысл `team` не менялся — это всегда был ответ детектора;
сторона на виде игрока — новое поле `side`. Причина в выходе — только при
`null`.

## В live

`lolstream/live.py` (`Session._step`, волна 3): записи юнитов детектора
проходят `assign(recs, SideContext(view, my_team, my_team_reason), fr)`:

* `view` — вид паспорта трансляции (docs/passport.md); `unknown` → `None`,
  отказ «вид неизвестен», а не наблюдатель. Детектор при неизвестном виде и
  не запускается;
* `my_team` — команда своего игрока из последнего `LiveStatus`
  (`game.my_player.team`), только если паспорт разрешает `api_facts` (API в
  игре); иначе `None` и причина паспорта («Live Client API: loading — …»),
  своего игрока нет — `me_reason`;
* `fr` — тот же кадр, по которому работал детектор.

Источник стороны — поле `side_src` у юнита и трека: `detector` (вид
наблюдателя, `team` детектора) или `api` (от своей команды). Сервис
состояния переводит `detector` в источник `screen`.

Смотрелка (`app.js`) на виде игрока (`row["view"] == "player"`) красит
юниты и треки по `relation` (сам — зелёный, свой — синий, враг — красный,
`null` — серый) и показывает в подсказке отношение, сторону с источником и
причину при `null`; у наблюдателя — по `team`, как раньше.

## Как проверить на записях своей игры

Готовность 2A — на записанных кадрах своей игры за обе стороны. Записи
делает `tools/record_own_game.py` (docs/own-recordings.md, 2D): кадры
`data/own/<запись>/full/*.jpg` и журнал Live Client API (команда своего игрока — `allPlayers[me].team`):

```bash
python tools/eval_units.py --frames "data/own/<запись>/full/*.jpg" --no-mask --name own-<сторона>   # видеокарта
python tools/eval_sides.py --preds runs/units/eval/own-<сторона>/preds.jsonl --my-team <ORDER|CHAOS> \
    --sheet runs/units/eval/own-<сторона>/sides.jpg --root <корень с data/>
```

Смотреть: доля отказов по причинам, `frames_with_several_self` = 0, на
листе плашек — свой зелёный «self», союзники «ally» со своей стороной, враги
«enemy» с другой, и за CHAOS сторона союзников CHAOS (не перевёрнута); доля
«цвет полоски и ответ детектора расходятся» у миньонов за CHAOS — ответ на
вопрос «тело или полоска». С разметкой `--gold` (формат — в докстринге
инструмента) — доля уверенных ошибок и отказов.
