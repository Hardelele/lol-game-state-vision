# MVP: сервис состояния игры для coach — ТЗ на этапы 1 и 2

Постановка для одной крупной сессии: управляющая сессия и команда агентов
доводят этапы 1 и 2 плана MVP (2026-10-12). Этап 0 (#788) закрыт.

## Зачем

Потребитель зрения — соседний репозиторий `C:\develop\games\lol\coach`
(«LoL Coach»): он захватывает экран игрока через MSS и на каждый вопрос
отправляет кадр языковой модели. Это ~5 с, деньги и выдумки. MVP — **локальный
сервис состояния**: несколько раз в секунду он отдаёт проверенные факты о
**собственной игре пользователя** (вид игрока, свой экран), на которых coach
подсказывает сам или опирается в ответах модели.

Два следствия, на которых стоит весь план:

1. **Основной случай — вид игрока со своего экрана**, а не YouTube
   наблюдателя. Аудит допущений (#781, комментарий 2026-10-12) показал, что
   именно там больше всего уверенной чуши.
2. **В своей игре есть Live Client Data API** (`https://127.0.0.1:2999/liveclientdata/`,
   официальный, самоподписанный сертификат). Он точно даёт время матча,
   десятерых чемпионов с командами, предметы, уровни, KDA, смерти и таймеры
   возрождения, события (убийства, драконы, барон, башни) и статы своего
   чемпиона. Зрение отвечает только за то, чего API не даёт: **где враги на
   миникарте, кто пропал, что на экране, где камера**.

## Роли

* **Управляющая сессия** — скептичный архитектор и интегратор. Сама почти не
  пишет код: ставит задачи агентам, держит границы модулей, ревьюит каждый
  дифф по чек-листу ниже, возвращает на доработку, вливает по одному, гоняет
  тесты после каждого слияния, ведёт трекер. Ничему не верит на слово: каждую
  цифру и каждое «работает» проверяет запуском или требует доказательство.
* **Агенты** (4–5, не больше) — по задаче на агента, каждый в своей ветке и
  своей рабочей копии. Один файл в один момент правит один агент: владелец
  `lolstream/live.py` назначается явно, остальные ждут или работают через
  интерфейсы.

## Архитектурные решения (заданы, не обсуждаются без причины)

* `lolvision/` — без сети, сервера и захвата экрана. Источники кадров, Live
  Client API и HTTP-выход — в `lolstream/`.
* **Источник кадров — интерфейс.** `FrameSource` (кадр RGB uint8 + время +
  размер + признак «есть ли кадр»): YouTube-поток (как сейчас) и экран
  (новый). Сеанс live не знает, откуда кадр. Сборка моделей сеанса выносится
  из `Session._work` в отдельную функцию/объект (`build_pipeline`), путь
  кадра — отдельно от сборки.
* **Типизированные записи** (`lolvision/records.py`, dataclass + `to_dict`)
  вместо позиционных списков для юнита, трека, чемпиона контекста и событий.
  Формат выхода версионирован (`schema: 1`). `app.js` читает поля по именам.
* **Одна проекция экран → карта** — `Projection` в `lolvision/geometry.py`;
  `MatchState` берёт места чемпионов с экрана через неё (или из трекера), а не
  «центр + доля вида».
* **Один хозяин состояния чемпиона** — `MatchState`. Трекер владеет экранными
  треками, читатели (`live_champions`, Live Client) — только наблюдения.
* **Отказ лучше выдумки.** Каждый выход либо значение, либо `null` с причиной
  (`reason`); никаких молчаливых запасных путей. Источник каждого факта —
  в выходе (`api` / `minimap` / `screen` / `hud` / `inferred`).
* **Приоритет источников:** Live Client API > HUD > зрение для того, что API
  даёт; зрение — для того, чего API не даёт. Расхождение источников — счётчик
  `conflicts` (сигнал #781), а не тихое перетирание.

## Этап 1. Вход и выход

**1A. Экран как источник кадров.** dxcam (DXGI, быстрый) с запасным MSS;
окно игры (`League of Legends (TM) Client`) — его прямоугольник, пауза, когда
окно не в фокусе или свёрнуто; ограничение кадр/с; кадры не 1080p — через путь
#788. Сеанс live принимает экран так же, как YouTube. Готово, когда: live
идёт по своему экрану в Practice Tool; замерены время на кадр и просадка FPS
игры (с моделями и без) — цифры в комментарии задачи; тесты источника на
синтетике.

**1B. Live Client Data API.** Чтение `allgamedata` (~2 Гц) и событий:
нет игры / загрузка / игра / конец — явные состояния, не исключения;
самоподписанный сертификат; типизированные записи (время, игроки: чемпион,
команда, ник, `isDead`, `respawnTimer`, уровень, предметы, счёт; свой
чемпион: статы; события с `EventID` без повторов). Тесты на фикстурах из
документации Riot (`liveclientdata_sample.json`, `liveclientdata_events.json`,
docs/pitfalls.md) и на записях своей игры. Готово, когда: тесты зелёные, в
Practice Tool чтение идёт без ошибок, отсутствие API не роняет сеанс.

**1C. Выход сервиса.** На loopback: HTTP-снимок состояния и поток событий
(SSE или WebSocket — выбрать и обосновать). Контракт — `docs/state-api.md`:
поля, единицы, источники, `null` + причина, версия схемы, пример. coach не
трогать, кроме, по согласованию, тонкого примера клиента. Готово, когда:
контракт описан, тест проверяет снимок на соответствие схеме, ручка работает
на живом сеансе.

**1D. Предпосылки из #787.** Записи `records.py` (см. выше) и переход на них
в live, трекере, контексте и смотрелке; `Projection` в `geometry.py`; места
чемпионов в `MatchState` через проекцию; выбор боевого детектора в одном
месте; тест склейки `Session._emit` на синтетике. Готово, когда: позиционных
списков в строке кадра нет, смотрелка работает (проверить в браузере), тесты
зелёные, ruff по затронутым файлам чистый.

## Этап 2. Верные ответы на виде игрока

**2A. Свои / враги / сам (#790).** На виде игрока цвета относительны: союзник
синий, враг красный, свой — зелёный/жёлтый. Выход: `ally` / `enemy` / `self`,
сторона ORDER/CHAOS — отдельно, из Live Client API (команда своего игрока).
`unit_bars.TEAM_BY_COLOR["player"]` уже есть. Цвет вне ожидаемого
(колорблайнд и пр.) → `null` + причина. Готово, когда: на записанных кадрах
своей игры за обе стороны команда верна, а у стримера за красных не
перевёрнута.

**2B. Состав и смерти из API (#791, #789 частично).** В своей игре состав,
смерти и таймеры возрождения — из Live Client API, `MatchState` принимает их
как источник `api`. Иконки миникарты назначаются только среди известных
десяти; имена над плашками на виде игрока не используются. Сброс памяти матча
по «смене состава» — только по сильному сигналу (новая игра в API). Готово,
когда: на записи своей игры состав верен в 100% кадров, смерти и возрождения
совпадают с API, ложных сбросов памяти нет.

**2C. Паспорт трансляции — минимум #781.** Объект ожиданий, построенный в
начале: источник (экран / YouTube), разрешение, прямоугольник игры, миникарта
(найдена, масштаб, совпадение), вид (наблюдатель / игрок / **неизвестен**),
есть ли Live Client API. Каждый читатель объявляет требования; не выполнены →
`null` + причина в выходе. Пересчёт пункта — по сигналу (совпадение миникарты
упало, API пропал, тип сцены сменился), не на каждом кадре. Готово, когда:
на виде игрока, наблюдателе и «неизвестной» раскладке выход честный — тест на
каждый случай и ручная проверка в live.

**2D. Проверочный набор (урезанный #792).** 3–5 записей своей игры или
Practice Tool (кадры + журнал Live Client API) за обе стороны; разметка —
истина из API там, где она есть, иначе «здесь должен быть отказ». Метрики по
каждому выходу: доля уверенных ошибок, доля отказов. Записи делает
пользователь — договориться с ним заранее, без них этап 2 не закрыть.
Хранение — `data/` (в git только манифест и разметка).

## Чек-лист ревью управляющей сессии

Дифф агента не вливается, пока не выполнено всё:

1. Границы слоёв: `lolvision` без сети и захвата; `tools/` не импортирует
   `tools/`; нет логики модели в `lolstream`, кроме обвязки.
2. Нет второго источника истины: констант, путей, проекций, выбора моделей.
3. Нет позиционных списков в новом коде; формат выхода совпадает с контрактом.
4. Нет молчаливых запасных путей: отказ — `null` + причина.
5. Тесты проверяют поведение, а не реализацию; новые ветви покрыты; полный
   `pytest` зелёный; ruff по затронутым файлам чистый.
6. Цифры в отчёте сняты запуском, с указанием на чём; непроверенное помечено.
7. Комментарии и докстринги по-русски, README по-английски, коммиты
   по-английски с `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
8. README (таблицы модулей и инструментов) и docs обновлены вместе с кодом.
9. Ничего не удалено из `data/`, `runs/`, `dataset/`.
