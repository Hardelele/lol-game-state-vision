# Кто это: состав матча, имя над плашкой, облик (#760)

Задача: для каждой найденной плашки чемпиона на основном виде канала
наблюдателя сказать, какой это чемпион. Плашки находит классический
читатель ([health-bars.md](health-bars.md)). Схема — как в
[entity-model-speed.md](entity-model-speed.md), п. 6: личность решается
внутри закреплённого состава из десяти и голосом по соседним кадрам, а не
классификатором облика на каждом кадре.

Цифры ниже измерены, если не помечено «оценка». Код: `lolvision/ddragon.py`,
`lolvision/roster.py`, `lolvision/name_reader.py`, `lolvision/appearance.py`,
`lolvision/identity.py`; скрипты `tools/ddragon.py`, `tools/identity_harvest.py`,
`tools/eval_roster.py`, `tools/train_names.py`, `tools/train_appearance.py`,
`tools/eval_identity.py`; тесты без данных — `tests/test_identity.py`.

## Данные

* **21 матч** канала Challenger Replays (KR и EUW, патч 26.19, 1080p):
  4 ролика из `data/videos` и 17 скачанных в `data/identity/videos`
  (после сбора удалены — дальше нужны только вырезы).
* `tools/identity_harvest.py` читает ролик один раз (ffmpeg, NVDEC,
  0.5 кадра/с) и пишет `data/identity/harvest/<id>.npz`: корреляции 20
  портретов HUD со всеми иконками, плашки (место, команда, ХП, уровень),
  вырез над плашкой (имя, 147×19) и под ней (облик, 192×192 → 128×128).
  Итого **17 677 кадров, 27 689 плашек**, 1.6 ГБ. Неполный ролик (поток
  оборвался) не сохраняется — проверка числа кадров по длительности.
* **Отложены** 58w57eJ5Qks (Volibear), olmTXkkUv58 (Ekko лес), 5nBGNokOUDA
  (Camille), 4AIX8QtRid4 (Ahri) — 4 960 плашек. Обучение — 17 остальных.
* Data Dragon 16.19.1 (= патч 26.19: с 2025 номер патча — год, а Data
  Dragon продолжил старую нумерацию, `ddragon.patch_to_version`): 173
  чемпиона, иконки, полные записи. Кэш — `data/ddragon/<версия>/`.

## 1. Состав матча по портретам HUD

**Как.** У канала портреты всех десяти видны всегда: нижняя таблица
(34×34 px, синие x 924, красные x 976, строки y 861 + 43.5·i) и боковые
панели (38×38 px, x 32 и 1848, строки y 160 + 102.75·i). Порядок строк в
таблице и панелях один — по ролям, так что у слота два вида. Портрет
сравнивается нормированной корреляцией с центром каждой иконки (без
восьмой части с краёв — рамка) со сдвигом ±3 px. Решение по ролику:
средняя корреляция по кадрам с HUD, сумма двух видов, назначение без
повторов (венгерский алгоритм — десять разных чемпионов).

**Портреты HUD — базовые иконки Data Dragon**, а не иконки скинов: на
опорном кадре корреляция с базовой иконкой 0.95–0.98, хотя на основном виде
у чемпионов скины. Исключение — чемпионы с формами: у **Kayn** в форме
портрет свой, такой иконки в Data Dragon нет. На a7p5Ql2LbAg слот Kayn
получил Kai'Sa со средней корреляцией 0.45; у остальных 209 слотов — 0.49–0.91,
ниже 0.55 только Viego (0.485). Поэтому слот с корреляцией ниже
0.5 проверяется по именам над плашками (`name_reader.refine_roster`):
медиана вырезов имени этого слота читается по всему словарю, и Kayn
получается с 0.72 против 0.64 у следующего. Viego (0.485) проверку прошёл
без замены.

**Результат** (`tools/eval_roster.py`, `runs/identity/roster_report.json`):

| | |
|---|---|
| Совпадение с названием ролика («Ekko Top vs Zac»: оба чемпиона, разные команды, одна роль) | **21 из 21** |
| Лист «портрет HUD — выбранная иконка» с середины каждого ролика, глазами | 209 из 210 совпадают (серые портреты погибших с таймером — тоже); 210-й — портрет Kayn в форме против иконки Kai'Sa, лист снят до поправки по именам |
| Слот по одному кадру = слот по ролику | 95.4% (среднее по роликам) |
| Все 10 по одному кадру = состав по ролику | 69% кадров |
| Накопленное решение стало окончательным | с первого кадра с HUD на 17 из 21 роликов; через 10–40 с на трёх; a7p5 — только поправкой по именам |
| Время | 34–51 мс на кадр CPU (numpy, машина загружена соседями); состав нужен раз в несколько секунд, не на каждом кадре |

Состав по одному кадру не всегда полон: «?» в таблице (чемпион в тумане),
серый портрет погибшего, цифра уровня поверх портрета. Решение по
накопленным кадрам эти помехи снимает.

Экран загрузки у стримеров для состава не делал: у канала наблюдателя HUD
есть с первой секунды игры, и состав по нему готов сразу.

## 2. Имя над плашкой

**Как.** Над плашкой канал пишет английское имя («Volibear», «Kai'Sa»)
или состояние («CHANNELING», «STUNNED», «AIRBORNE»…). Словарь закрыт:
173 имени, 21 состояние и две другие надписи, встреченные на отложенных
роликах, — «Mega Gnar» (форма Gnar) и «Harmless Critter» (превращение от
Lulu). OCR не нужен: вырез сравнивается с образцами целиком, как уровень в
health_bars. Признак — белизна (минимум по RGB), нормированная корреляция
со сдвигом ±4 px по x и ±2 px по y.

Образцы:
* **отрисованные** шрифтом Windows — для каждого слова словаря. Шрифт и
  кегль выбраны перебором 7 шрифтов × 3 кегля × 4 разрядки по согласию с
  разметкой составом: Constantia 12 px (состояния — разрядка 0.5 px, ниже и
  правее имени: слева значок эффекта);
* **настоящие** — медиана вырезов чемпиона, размеченных автоматически:
  плашка команды T несёт имя одного из пяти чемпионов T по составу. Три
  прохода: разметка → медианы → разметка по медианам. Медиана двух меток
  одного ролика, совпавшая со сдвигом (сходство > 0.85), — одно слово;
  остаётся метка с большим числом вырезов. Без этого медиана «Ezreal» на
  5nBGNokOUDA была словом Camille (отрисованные образцы путают эти имена
  даже на чистой медиане: 0.61 и 0.61).
* **подстройка под матч** (`name_reader.adapted`): медианы уверенно
  прочитанных вырезов этого матча добавляются к банку. Нужна для чемпионов
  без настоящего образца: на отрисованном сходство 0.5–0.6.

Итоговый банк — 175 настоящих образцов (90 чемпионов из 17 обучающих
роликов) + отрисованные для остальных 83 чемпионов и состояний
(`runs/identity/names.npz`). Имя считается прочитанным при сходстве ≥ 0.6
и отрыве ≥ 0.05 от второго из пяти кандидатов команды.

**Результат на отложенных роликах** (`tools/train_names.py`,
`runs/identity/names_report.json`, листы `names_check_<id>.png`):

| | |
|---|---|
| Проверенная выборка: 4 × 90 случайных вырезов, глазами | **342 прочитано, ошибок 0** (95%-я нижняя граница точности ≈ 99.1%, правило трёх) |
| Из них вырезов с видимой надписью | 355 (5 — пусто или текст объявления); не прочитано 13: перекрыто другой плашкой, имя наполовину за краем, одно CHARMED с малым отрывом |
| Плашек с уверенно прочитанным именем чемпиона, все отложенные (с подстройкой под матч) | 889 из 1 009, 1 030 из 1 187, 964 из 1 099, 1 435 из 1 665 — 4 318 из 4 960 (87%; остальное — состояния, пустые и перекрытые) |
| Имя по всему словарю (без состава) = имя среди пяти кандидатов | 95.5–99.6% по роликам |
| Время | 0.5–0.7 мс на плашку, CPU |

Без состава словарь работает хуже ровно на чемпионах без настоящего
образца: на выборке Kai'Sa читалась как Anivia/Kalista/Karthus, Kindred —
как Katarina, Gnar — как Galio, Zyra — как Zeri, Leona — как Janna.
Внутри пяти кандидатов команды таких ошибок нет.

## 3. Облик под плашкой

**Как.** Замороженный DINOv2 ViT-S/14 по вырезу облика, увеличенному до
224×224; признак — среднее патч-токенов центрального окна 6×6 из 16×16
(там, где под плашкой стоит модель), 384 числа. Центр по ближайшему соседу
лучше CLS и среднего по всему вырезу (на трёх роликах 86/97/77% против
85/97/76% и 83/97/74%). Метки — прочитанные имена («HUD как учитель»).

Три классификатора, все выбирают среди пяти чемпионов команды плашки.
Проверка — на плашках отложенных роликов с прочитанным именем; прототипы
не ближе 30 с к проверяемому кадру (offline) или только из прошлого
(online, как в live).

| | 58w | olmT | 5nBG | 4AIX | всего (4 318) |
|---|---|---|---|---|---|
| общая линейная голова (91 чемпион обучения) | 18.2% | 74.0% | 68.8% | 65.5% | 58.5% |
| прототипы матча, сырые признаки, offline | 87.0% | 82.1% | 89.2% | 85.7% | 85.9% |
| прототипы матча, своя проекция, offline | 90.7% | 87.6% | 93.6% | 91.5% | **90.9%** |
| то же, online (только прошлое) | 85.7% | 83.6% | 89.6% | 85.7% | 86.1% |

* **Общая голова** не годится: у 13 из 40 чемпионов отложенных составов
  нет ни одного обучающего выреза (на 58w — у Volibear, Irelia, Evelynn,
  Zyra), и даже знакомых она путает между скинами.
* **Прототипы матча** — ближайший вырез того же ролика с прочитанным
  именем. Скин, хрома и форма у прототипа те же, что у запроса, поэтому
  устойчивость к скинам получается сама собой. Ближайший (k = 1), а не
  среднее пяти: при k = 5 частый ведомый чемпион перетягивал редких.
* **Своя проекция** (384 → 128, косинусный классификатор на 19 729
  вырезах 91 чемпиона обучения, `runs/identity/appearance_proj.npy`) —
  пространство, где соседи меньше смотрят на фон и больше на модель.
  Чемпионов она не называет, только меряет сходство, поэтому работает и
  для невиданных: +5 пунктов к сырым признакам.
* Время: 11.8 мс на 4 выреза (типичное число плашек на кадре), RTX 5060 Ti
  под нагрузкой соседних задач, fp16.

## 4. Объединение

На плашку: прочитанное имя — ответ; без имени — облик × неуверенное
чтение имени (часть букв часто видна). Затем голос соседних кадров (±2 с)
«с той же плашкой» — та же команда, уровень ±1, ближе 350 px (вес 0.5) — и
запрет двух одинаковых чемпионов в одной команде на кадре (венгерский
алгоритм). Трекера нет: при 0.5 кадра/с камера наблюдателя за 2 с уходит
на сотни пикселей, поэтому соседи — голос, а не жёсткая связь. Сосед
нашёлся у 90–95% плашек.

**Как меряем.** Верной метки для плашки без имени нет. Поэтому проверка —
на плашках с прочитанным именем: имя этой плашки прячем (оно не идёт ни в
ответ, ни в прототипы ±30 с), отвечаем обликом и соседями, сравниваем с
прочитанным именем (`tools/eval_identity.py`, `runs/identity/identity_report.json`).

| имя спрятано, 4 318 плашек | offline | online |
|---|---|---|
| только облик | 90.9% | 87.0% |
| + соседние кадры | 93.1% | 90.3% |
| + разные чемпионы в команде на кадре | **96.5%** | **94.6%** |
| то же, средняя по чемпионам (редкие весят как частые) | 80–93% по роликам | 71–89% |

Итог «кто это» для найденных плашек:
* 87% плашек — с уверенно прочитанным именем: на выборке 342 из 342 верно;
* остальные 13% — состояния, перекрытые и пустые: по спрятанным именам
  оценка 94.6–96.5%; на листах `identity_check_<id>.png` (48 плашек без
  имени на ролик) там, где имя глазами всё же видно, ответ ему
  соответствует, кроме плашек под открытым Tab и скрытых HUD (облик закрыт
  таблицей).

Оценка на все плашки (не мерилась целиком): 0.87 · ~1.0 + 0.13 · ~0.95 ≈
99%.

## Провалы и ограничения

* **Редкие чемпионы.** Средняя по чемпионам ниже средней по плашкам: у
  Ekko на 5nBG 0 из 4, у Qiyana 1 из 3, у Jayce на olmT 9 из 16. Мало
  прочитанных имён — мало прототипов, и облик тянется к частому соседу.
* **Формы.** «Mega Gnar» сначала не читалась (ошибка в сборке банка:
  дубли метки получали первый образец) — после исправления читается
  (0.67–0.76). Облик Mega Gnar от обычного Gnar далёк: без имени она
  уходила в Kindred. Прототипы матча формы переживают, только когда у
  формы есть свои прочитанные имена. Elise, Nidalee, Jayce, Quinn/Valor,
  эволюция ультимейт-скинов отдельно не проверялись.
* **Клоны.** Neeko в облике союзника пишет над плашкой его имя; двойники
  Шако, Леблан, Вуконга, Фиддлстикса и Виего в облике убитого — тоже
  обманут и имя, и облик. Ограничение «пять разных в команде на кадре»
  здесь мешает: двойник честно занимает вторую плашку того же имени. Не
  решено; запас — Live Client Data (ниже).
* **Иконки HUD не из Data Dragon** — у чемпионов с формами (Kayn). Ловится
  по низкой корреляции и правится по именам; при кадрах без плашек этого
  чемпиона слот останется неверным.
* **Tab и панели поверх основного вида** закрывают облик; плашка там
  находится, а облик — таблица.
* **Сдвинутые плашки** (найденные со смещением, health-bars.md) дают
  обрезанное имя.
* Проверено только на канале наблюдателя одной сети при 1080p.
  Вид игрока у стримеров и другие раскладки HUD не проверялись.
* Data Dragon может отставать от патча на день-два: нового чемпиона без
  иконки состав не узнает (Locke в 16.19.1 уже есть).

## Скорость на кадр

| часть | время | где |
|---|---|---|
| плашки (health_bars) | 330–450 мс | CPU, под нагрузкой; известная узкая часть, план — на GPU |
| состав по HUD | 34–51 мс | CPU; нужен раз в несколько секунд |
| имя | 0.5–0.7 мс на плашку | CPU |
| облик | 11.8 мс на 4 плашки | GPU |
| голос соседей, назначение | доли мс (оценка, не мерилось) | CPU |

Для live облик нужен только плашкам без уверенного имени (13%) и новым
трекам, имя — раз на трек и при сомнении (оценка: < 5 мс на кадр сверх
поиска плашек).

## Что дадут Replay API и Live Client Data

По [replay-render.md](replay-render.md), `/liveclientdata/playerlist` в
реплее отдаёт для всех десяти чемпиона, команду, уровень, предметы,
`skinID`/`skinName` и экранные позиции.

* **Проверка без глаз.** Состав и личность каждой плашки на отрендеренных
  кадрах (по `screenPositionBottom`) — точные метки: точность имени и
  облика можно будет мерить на всех плашках, включая статусы и перекрытые,
  а не на выборке и спрятанных именах.
* **Скины.** `skinID` даёт метку скина: проверить, где облик путается
  (новые скины — главный провал в Honor of Kings), и собрать прототипы по
  скинам заранее, а не только по ходу матча.
* **Клоны и формы.** Позиции десяти настоящих чемпионов отличат Neeko и
  двойников от оригинала; рендер с `noBars` (без плашек) отделит модель от
  надписей.
* На YouTube-роликах этого нет — Replay API остаётся источником меток для
  обучения, вход модели — кадр.

## Что дальше

1. Трекер по плашкам на каждом кадре (сдвиг камеры из модели камеры как
   компенсация движения) — голос по треку вместо соседних кадров.
2. Уровень из боковых панелей HUD: у плашки уровень известен, у каждого из
   десяти в панели — тоже; совпадение уровня — сильный голос (уровень до 20
   у верхней линии с 26.1).
3. Метки из Replay API (выше) — цифры на всех плашках и по скинам.
4. Поиск плашек на GPU — он сейчас главная часть времени.

## Как повторить

```
python tools/ddragon.py --patch 26.19 --full        # кэш Data Dragon
python tools/identity_harvest.py --all              # сбор: data/identity/harvest/*.npz
python tools/eval_roster.py                         # состав
python tools/train_names.py --heldout 58w57eJ5Qks olmTXkkUv58 5nBGNokOUDA 4AIX8QtRid4
python tools/train_appearance.py --heldout 58w57eJ5Qks olmTXkkUv58 5nBGNokOUDA 4AIX8QtRid4
python tools/eval_identity.py --heldout 58w57eJ5Qks olmTXkkUv58 5nBGNokOUDA 4AIX8QtRid4
```

Ролики берутся из `data/videos` и `data/identity/videos` (yt-dlp, формат
399 или лучший 1080p, через прокси). Отчёты и банки — в `runs/identity/`.
