# Разведка рендера Replay API (#755, этап 0)

Проверка того, на чём стоит путь A плана второй модели
([entity-model-plan.md](entity-model-plan.md)): разметка юнитов как
разность рендеров одного момента. Инструмент — `tools/replay_render.py`,
снимки — `data/replay/render/<сцена>/` (PNG без потерь, `meta.json` с
камерой, составом и позициями). Реплей: матч патча 16.20, 1920×1080.

Сцены: бой у ямы дракона на 40:00 (8 чемпионов на экране,
`tf2400`, `tf2400b`), три линии на 5:00 (`bot300`, `mid300`, `top300`),
река на 15:00 (`river900`), пустой лес в тумане (`fog900`).

## Коротко

* **Пауза статична.** Два снимка подряд на паузе совпадают, если убрать
  курсор с поля. Шумовой карты и порогов не нужно.
* **Флаг применяется за ~0.3 с**, дальше кадр не меняется. Один вариант
  рендера — 0.6 с (смена флагов, ожидание 0.35 с, снимок).
* **Флаги `champions`, `minions`, плашки выключают ровно своё**: разность
  с полным кадром даёт маску чемпионов, миньонов, каждой плашки отдельно.
* **Позиции чемпионов даёт Live Client Data API**, привязка камеры не
  нужна: `screenPositionBottom/Center` в `/liveclientdata/playerlist` —
  проекция трёхмерного положения чемпиона нашей формулой камеры.
  Две точки съёмки → положение в мире с ошибкой ~1 ед.
* **Состав и облик**: `playerlist` в реплее отдаёт чемпиона, игрока,
  команду, уровень, предметы и `skinID`/`skinName`.
* **Расхождение с роликами канала: плашка чемпиона здесь 134–136 px в
  ширину, у канала 117–118.** До сбора данных выровнять масштаб.

## Флаг → что пропадает

Доля изменившихся пикселей против полного кадра (порог 24 по любому
каналу), по сценам `tf2400b` / `mid300` / `bot300` / `fog900`.

| Вариант | Флаги | Изменилось, % | Что пропадает |
|---|---|---|---|
| `full2` | — | 0.00 / 0.00 / 0.00 / 0.00 | ничего (единичные пиксели) |
| `clean` | `interfaceAll=false` | 9.7 / 9.2 / 9.1 / 6.6 | весь HUD реплея: счёт, миникарта, таймлайн, панель камеры. Плашки над юнитами **остаются** |
| `noBars` | все `healthBar*`, `floatingText` | 0.41 / 0.56 / 0.33 / 0 | плашки всех юнитов с именами и уровнем |
| `noChampBars` | `healthBarChampions` | 0.37 / 0.17 / 0.32 / 0 | только плашки чемпионов |
| `noMinionBars` | `healthBarMinions` | 0.01 / 0.08 / 0 / 0 | только плашки миньонов |
| `noChamp` | `champions=false` | 4.1 / 0.54 / 0.69 / 0 | модели чемпионов вместе с их эффектами и тенью; плашка остаётся |
| `noMinion` | `minions=false` | 0.22 / 3.6 / 0.28 / 0 | миньоны (на миде — толпа у башни) |

| `noFog` | `fogOfWar=false` | 0.89 / 8.1 / 12.6 / 72 | затемнение тумана на поле и на миникарте |
| `noEnv` | `environment=false` | 83 / 83 / 89 / 87 | карта; вместо неё плоская светло-зелёная заливка с бликами, юниты и эффекты остаются |
| `noOutline` | `outline*` | 0.00–0.01 | контур под курсором (если курсор убран — ничего) |
| `noTextOnly` | `floatingText` | 0.00–0.01 | всплывающие числа (на паузе их почти нет) |

Выводы для разметки:

* Маска чемпионов — `full − noChamp`; миньонов — `full − noMinion`;
  остальные юниты — `(full − noChar)` минус первые две.
* `noEnv` не даёт чистой маски: фон не однотонный, эффекты остаются.
  Вместо него — разности по флагам юнитов.
* Плашки отдельно по типам — `full − noChampBars`, `full − noMinionBars`.
  Плашки двух близких чемпионов сливаются в одну компоненту (у Чо'Гата и
  Экко на `river900` — 193 px): делить по экранным точкам из API.
* `interfaceAll=false` плашки не убирает: HUD и плашки — разные слои, как
  и нужно для аугментации «другой HUD».

**Не выяснено.** На кадрах всех сцен есть бело-фиолетовые знаки
(похожи на сюрикен), их не убирает ни один флаг, даже `environment` и
`characters`. Возможно, это украшение карты от события или скин
варда — проверить в клиенте.

## Позиции чемпионов: Live Client Data API

`selectionName` + `cameraAttached` камеру к юниту **не привязывают**: ни на
паузе, ни при воспроизведении, ни в режимах `fps`/`top`/`focus`/`path`.
Клиент только переписывает `selectionName` в игровое имя игрока
(`Ambessa` → `Ken`).

Зато в `/liveclientdata/playerlist` есть `screenPositionBottom` и
`screenPositionCenter`. Для чемпионов рядом с камерой это пиксели экрана
(могут быть и за кадром), для дальних — `FLT_MAX`. Они пересчитываются при
сдвиге камеры на паузе. Сдвиг камеры по x меняет только экранный x, по
z — оба, как в перспективе.

Проверка: при шести положениях камеры луч через `screenPositionBottom`
пересекается с горизонтальной плоскостью в одной точке с разбросом
0.1–1.2 ед. (8 чемпионов), если высоту плоскости подобрать для каждого
чемпиона. Модель камеры при этом наша: глаз в `cameraPosition`, тангаж
`cameraRotation.y` = 56°, **`fieldOfView` = 40° по вертикали** (с
горизонтальным FOV разброс 100–190 ед.). Отсюда
`replay_render.world_positions`: второй снимок экранных точек с камерой,
сдвинутой на 400 ед., и триангуляция двух лучей → (x, высота, z) каждого
чемпиона в кадре. Это эталон позиции для этапа 5 вместо привязки камеры.

Насколько точка API совпадает с нарисованной моделью (центр маски
`full − noChamp` против `screenPositionCenter`): на линиях и в реке
расхождение от 0 до 55 px в обе стороны, без постоянного сдвига. Это поза
и размер модели. В яме дракона все точки API на 50–150 px ниже моделей.
Вероятно, клиент берёт высоту не рельефа ямы. Точнее разобрать по маскам
на большем числе сцен на этапе 2. «Высота» из триангуляции — 50–180 ед.:
это точка модели, а не земля.

## Время и объём

* Смена флагов + ожидание 0.35 с + снимок: **0.6 с на вариант**. Перенос
  камеры с ожиданием — 0.4 с, позиции чемпионов (второй ракурс) — 0.7 с.
* Для разметки достаточно 6 вариантов (`full`, `noChampBars`,
  `noMinionBars`, `noChamp`, `noMinion`, `noChar`): **~5 с на точку,
  ~700 точек в час**. В плане было 2000. Ускорение — снимать через Windows
  Graphics Capture вместо `ImageGrab` и сократить ожидание.
* Полный кадр PNG ~2.3 МБ; 14 вариантов — ~30 МБ на точку. Для сбора
  хранить `full` в JPEG, а маски — бинарными PNG.

## Что изменилось в плане

* Позиция на карте — из `playerlist` триангуляцией, а не привязкой
  камеры (пункт «Позиция на карте» пути A).
* Шумовая карта не нужна: пауза статична. Курсор — в угол.
* Перед этапом 2 выровнять масштаб плашек с каналом (134–136 px против
  117–118). Если это не выйдет настройкой, масштабировать кадры реплея
  по ширине плашки.
* Оценка скорости сбора — ~700 точек в час, а не 2000.

## Воспроизведение

```
python tools/replay_render.py scout --time 2400            # где больше чемпионов
python tools/replay_render.py settle --time 2400 --x 10143 --z 4657
python tools/replay_render.py flags --time 2400 --x 10143 --z 4657 --name tf2400b
```
