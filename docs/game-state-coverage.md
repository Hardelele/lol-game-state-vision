# Что из состояния игры мы уже получаем с кадра, а что нет

Сводка на 2026-10-11 (main, d185e0a). Источник — кадр трансляции: основной
вид, миникарта, HUD канала наблюдателя (Volibear Challenger Replays: табло
сверху, боковые панели, нижняя таблица всех десяти, панель ведомого
чемпиона, таймеры объектов, килфид), Tab, вид игрока у стримеров. Replay
API и Live Client Data — только источник меток для обучения, не вход.

Обозначения: **есть** — работает и измерено; **частично** — работает в
узких условиях; **план** — есть план или разведка, кода нет; **нет** —
не начато.

## Что из этого следует

* Сейчас покрыто «где смотрим» и «что на экране»; из состояния самих
  игроков — только плашки видимых чемпионов на одном канале.
* Больше всего информации при наименьших усилиях — **HUD канала
  наблюдателя**: нижняя таблица (предметы, KDA, крипы всех десяти),
  табло сверху (время, убийства, золото, башни, объекты), таймеры
  объектов, боковые панели (уровень, ХП, ресурс, заклинания, смерть).
  Раскладка известна, области измерены; цифры читаются тем же приёмом,
  что уровень на плашке, иконки предметов и чемпионов — классификатором
  по образцам Data Dragon. Это покрывает почти весь блок «каждый
  чемпион» для канала.
* **Миникарта** — второй по отдачи источник: положения всех видимых
  чемпионов, башни, варды, таймеры лагерей. Иконки миникарты всегда
  базовые (без скинов), готовые проекты по миникарте есть
  (docs/entity-model-plan.md, раздел 1.2).
* **Основной вид** (#757) нужен для того, чего нет в HUD и на
  миникарте: миньоны и монстры с ХП, бой, эффекты, варды в кадре,
  точные позиции.
* **Tab** даёт полную таблицу у стримеров, где нижней таблицы нет;
  тип сцены уже говорит, когда его читать.
* Чтение HUD конкретного канала — быстрый результат; работа при любом
  HUD (#757) — следующий шаг, где эти читатели станут источниками меток.
