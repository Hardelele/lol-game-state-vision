# Готовность своих заклинаний D/F по HUD (#806)

Код — `lolvision/hud_spells.py` (поиск панели, признаки, решение по слоту,
`SpellHud` сеанса), инструмент данных и проверки — `tools/hud_spells.py`,
тесты — `tests/test_hud_spells.py`, в сеансе — `lolstream/live.py`
(`_spells_step`), выход — `me.spells_ready` и `me.spells_hud` в /state
([state-api.md](state-api.md)), читатель паспорта — `hud_spells`
([passport.md](passport.md)).

Live Client API говорит, какие заклинания взяты, но не говорит, готовы ли
они (#804). Готовность видна только на HUD вида игрока.

## Что на иконке

Замер по 10 роликам вида игрока (ниже) и кадрам своей игры:

| Вид слота | Как выглядит | Ответ |
| --- | --- | --- |
| готово | яркая иконка заклинания; у Кары — число зарядов в углу и след перезарядки второго заряда (белая черта по кругу) | `true` |
| перезарядка, начало и середина | ровная тёмно-синяя заливка сектора «осталось» + белые цифры с тёмной обводкой (`300`, `2:50`, `0.4`) | `false` |
| перезарядка, конец, и короткие (запрет повтора Кары 15 с) | синего почти нет: иконка тёмная, цифры есть | `false` |
| запрет | иконка темнеет, поверх красный крестик (контроль, своё умение) | `null` |
| все умения серые при полном ХП | серая иконка без цифр (неизвестная причина: на роликах Jax, Pantheon) | `null` |
| смерть | панель серая, полоса ХП пуста; **синяя заливка перезарядки остаётся** | готовое — `null`; на перезарядке — `false` |
| панели нет | загрузка, заставка стримера, экран конца | `null` |

Из этого следуют две ловушки абсолютных порогов (обе — замерены):

* признак «белые цифры с обводкой» у готового Призрака своего HUD (белая
  фигура) — 0,19–0,21 доли середины иконки, у цифр перезарядки — 0,04–0,11
  (#804: 30 из 32 ложных);
* доля «синих» пикселей у готового голубого Призрака (ролик ANXVB571YkE) —
  0,31–0,32 и у синей Кары — до 0,5, как у заливки перезарядки в конце.
  Отличает их рисунок: у заливки перепад яркости у соседних пикселей
  (Собель |gx|+|gy|) 80–150, у синих пикселей иконок — 190–320. Признак
  `navy` считает только ровные синие пиксели: у готовых синих иконок
  0,10–0,23, у перезарядки 0,34–0,78; и вдобавок требует тёмную иконку
  (средняя яркость < 140; у Призрака 179).

## Метод

1. **Панель умений** (`locate_panel`). Эталон — вырез панели своего HUD
   (`dataset/hud_spells/panel_template.png`, медиана 32 кадров своей игры
   1920×1080, Practice Tool). Сравнение NCC в сером по рамкам и фону панели;
   иконки, цифры, полосы ХП/маны, точки уровней, подписи клавиш и портрет
   закрыты маской — так эталон не зависит от чемпиона и заклинаний. Масштаб —
   сетка 0,70–1,60 с шагом 0,02 (грубо — по картинке вдвое меньше, точно —
   ±12 px вокруг лучшего); слоты — постоянные прямоугольники в координатах
   эталона, умноженные на масштаб. На роликах масштаб HUD 0,96–1,28 от
   своего (иконка 26–35 px при 1080p), свой HUD — 1,00 (иконка 27 px).
   В сеансе панель считается найденной после 3 находок подряд в одном месте
   (±4 px, ±0,03 масштаба) с совпадением ≥ 0,52; есть ли панель на кадре —
   совпадение на найденном месте ≥ 0,35.
2. **Признаки слота** (`slot_features`, вырез 24×24 без рамки): средняя
   яркость и насыщенность, доля ровной синей заливки, доля белых пикселей с
   тёмной обводкой в середине (цифры), красный крестик (доля чисто красных
   пикселей на диагоналях минус вне их: у крестика 0,29–0,49, у
   Воспламенения ≤ 0,01).
3. **Эталон готовой иконки — свой у каждого слота, набирается в сеансе**
   (`SlotRef`): медиана последних 40 вырезов (не чаще одного за 2 с),
   которые не похожи на перезарядку (ровной синей заливки < 0,25 или иконка
   яркая), без крестика, не у мёртвого, без «тёмная с цифрами». Отвечать
   «готово» — только когда в эталоне ≥ 8 вырезов (≈ 16 с потока). Заклинание
   слота по API сменилось (улучшенный Телепорт, стадии Кары) — эталон слота
   заново (`SpellHud.set_spells`); без API эталон сам переходит на новую
   иконку за ~40 с.
4. **Решение** (`decide`), по порядку: панели нет → `hidden`; крестик →
   `blocked`; ровная синяя заливка сверх эталона ≥ 0,30 и иконка тёмная →
   `cooldown`; иконка темнее 0,7 эталона и цифры ≥ 0,03 (не у мёртвого) →
   `cooldown`; мёртв (полоса ХП пуста) → `dead`; похоже на эталон (NCC ≥ 0,8,
   яркость ≥ 0,8 эталона, насыщенность ≥ 0,7 эталона, синего и цифр не
   больше эталона) → `ready`; иначе `unsure`. «Готово» — только когда
   сходятся все признаки; любое сомнение — `null`.

Относительное сравнение с собственной готовой иконкой, а не абсолютные
пороги: у готового Призрака белая фигура есть и в эталоне, у синей Кары
синие пиксели — тоже; а перезарядка, серость и крестик меняют иконку
относительно её же готового вида одинаково у всех заклинаний.

Секунд до готовности (`me.spells_cooldown`) нет: цифры видны, но образцов
шрифта D/F на разных масштабах не набрано, а отсчёт по времени от начала
перезарядки требует полной перезарядки заклинания с учётом ускорения — не
сделано.

## Умения Q/W/E/R: эталон из Data Dragon (#849)

Тот же читатель читает умения (`me.abilities_ready`, `abilities_hud`). У
части иконок умений сама картинка синяя или тёмная: готовая Q Волибира —
ровных синих 0,44 при яркости 113, Q Ашки — 0,29 и 124 (по иконкам Data
Dragon 16.20.1 так 137 из 692). Без эталона правило «синяя заливка и
тёмная» отдавало у готовой Q Волибира `cooldown`, а набрать эталон такая
иконка не может (кандидат должен быть не синим или ярким). Отчёт с
замерами — `bc-data/CASTS.md`, раздел 3.

Поэтому, когда свой чемпион известен (API `me.champion`, у роликов —
`--roster`), эталон «готова» умения — его иконка Data Dragon
(`SpellHud.set_champion`, `ability_icons`): внутренность с тем же
отступом `INSET`, 24×24. Иконки — только из кэша, без сети
(`lolstream.live.ability_icons`: `data/ddragon/` и кэш индексатора
`BC_INDEX/ddragon`, его наполняет `tools/video_index.py assets`); нет
иконок — умения читаются по набранному эталону, как D/F. Решение
(`_decide_icon`): крестик → `blocked`; правила перезарядки — те же, но
синева и яркость сравниваются с признаками иконки; мёртв → `dead`; NCC с
иконкой ≥ 0,70, яркость ≥ 0,75 и насыщенность ≥ 0,6 иконки, синего и цифр
не больше → `ready`; жёлтая рамка вокруг слота (`slot_ring`: доля
ярко-жёлтых пикселей кольца ≥ 0,10; у активной Q 0,21–0,26, у остальных 0)
→ `active` (`false`: умение действует); иначе `unsure`. Тёмная иконка без
рамки (все умения гаснут разом под контролем) по вырезу от активной не
отличается (яркость 44, насыщенность 0,21 у обеих) — только по рамке.

Нажатия по ряду состояний — `hud_spells.presses`: первый кадр после
последнего `ready`, если не позже 3,5 с `cooldown` или `active`; плюс
начало `active` (≥ 0,35 с подряд) без `ready` перед ним — Q нажата в первый
же кадр готовности, по концу перезарядки или крестика.

Проверка на своих играх, 10 к/с, только HUD (вырезы слотов по всему видео,
решение старым и новым путём; нажатия — `presses` для обоих):

| | старый | новый |
| --- | --- | --- |
| Волибир 14.10, Q (`.mkv`, 1377 с) | 55 «нажатий», из 8 известных ни одно не ближе 0,7 с (ошибка −2,9…+13,9 с) | 77; 8/8 известных, ошибка −0,2…+0,15 с; 20 случайных и 7 «по концу перезарядки» по листам глазами — все настоящие; ни одного цикла «активна» без нажатия |
| Волибир, W/E/R | 43 / 53 / 9 | 44 / 55 / 9: все старые на месте, плюс W 9,2, E 7,7, E 23,1 в первые 30 с (эталон старого ещё не набран) |
| Ашка 14.10, Q | 0 | 17: по листу у всех рамка «готова» → тёмная с рамкой |
| Ашка, W/E/R | 28 / 3 / 0 | 30 / 3 / 6 (W 24,9 и 44,2 — первые секунды; R — готова → `1:xx`) |
| D/F обеих игр | — | состояния кадр в кадр те же |

Готовая Q Ашки — только с 4 зарядами (иконка яркая, затем рамка); до того
иконка тусклая — `unsure`. Видео игры на Бренде нет (журнал API есть).

Не сделано: иконки второй стадии (W2 Волибира, Q2/Q3 Атрокса, R Нидали —
читаются `unsure`), смена облика иконки скином (иконки умений от облика не
зависят), перезарядка Волибира у мёртвого (синяя Q у мёртвого — `dead`).

## Не проверено

* перезарядка на своём HUD (кадров нет) и на живом сеансе целиком;
* масштабы HUD меньше 0,96 и больше 1,28, разрешения кроме 1080p (поиск
  масштабирует эталон, но на таких кадрах не проверен);
* Исцеление, Барьер, Изнурение, Очищение (Исцеление — только на ролике
  подбора 8lkxSQHq81k), режимы кроме Ущелья (ARAM — 15 кадров);
* HUD, сдвинутый настройками (у ShokLeague миникарта слева и HUD сдвинут),
  цветовые фильтры для дальтоников;
* секунды до готовности (`spells_cooldown`) — не сделаны.
